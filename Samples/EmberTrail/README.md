# Ember Trail — Conqueror's Engine sample

An original 2D pixel-art platformer. Wick, a little candle spirit, runs through three worlds to light the great
lanterns. Built only with engine features: ConquerorScript, the Tilemap with 16-tile autotiling, sprites and
sprite-sheet animation, 2D lights (the caves), particles, the UGUI canvas, the audio mixer and PlayerPrefs.

Open `EmberTrail.cqproj` in the editor and press **Play** (the game starts on the title / level-select screen),
or build it from **Build → Build Settings**.

## Gameplay

- Run with acceleration, variable-height jump, coyote time and jump buffering
- **Dash** (in the air or on the ground) once per jump: dashes through any enemy
- Stomp slugs and moths; thorn beetles can only be dashed through
- Springs, one-way planks, moving platforms (horizontal and vertical), crumbling bridges, spikes
- Checkpoint lanterns; a fall puts you back at the last lit lantern
- Every level has embers to collect and three hidden **sun shards**; the results screen rates your time with a
  gold / silver / bronze flame, and the level select shows your best times, shards and medals

| World          | Levels                         | Look                                         |
|----------------|--------------------------------|----------------------------------------------|
| Sunny Meadow   | 1-1 Sunny Start, 1-2 Windy Hills  | Grass, rolling hills, clouds              |
| Glowcap Caves  | 2-1 Glowcap Cavern, 2-2 Crystal Depths | Dark caves lit by Wick's flame and the lanterns |
| Cloud Kingdom  | 3-1 Cloud Ruins, 3-2 Lantern Peak | Marble ruins above a sunset sky            |

Levels unlock one after another.

## How the levels are made and tested

The simulation in `Assets/Scripts/EmberGame.cqs` (player, enemies, platforms, crumbling blocks) runs at a fixed
1/60 s and is mirrored line by line in `Tools/ember_sim.py`. Both use only exact arithmetic (no sine/cosine for moving
things), so a sequence of inputs gives the same result in Python and in the engine.

`Tools/gen_levels.py` builds the six levels from the pieces in `Tools/ember_levels.py`, runs a beam search
(`Tools/ember_solve.py`) that finds a way to the goal lantern, and writes the scene builders to `Tools/Levels/`
with the solution stored in each scene. A level the solver cannot finish is rejected. The automated tests replay
every solution in the engine with the autopilot and check that it reaches the lantern on the same tick and at the
same position as in Python.

To change a level: edit its piece list in `Tools/ember_levels.py`, run `python3 Tools/gen_levels.py`, then build the
scenes in the editor with `CQ_AUTOMATION=Tools/Levels/build_levels.txt`.

## Project layout

| Path                              | Contents                                                       |
|-----------------------------------|----------------------------------------------------------------|
| `Assets/Scenes/Menu.cqscene`      | Title screen and level select (start scene)                     |
| `Assets/Scenes/<World><N>.cqscene`| The six levels                                                 |
| `Assets/Scripts/EmberGame.cqs`    | Level: simulation, input, animation, camera, HUD, pause, results |
| `Assets/Scripts/EmberMenu.cqs`    | Level select, unlocks, records                                 |
| `Tools/gen_assets.py`             | Generates every texture, sound effect and music track           |
| `Tools/ember_levels.py`, `ember_sim.py`, `ember_solve.py`, `gen_levels.py` | Level pieces, physics mirror, solver, scene generator |
